# Validation Rules

Use these checks before considering a file complete or ready to share.

## 1. Required structure check
- Confirm the file includes all required sections for its type.
- For markdown documents, verify headings are present in the expected order.
- For code files, confirm imports, config, and function/class definitions are in the correct locations.

## 2. Accuracy and consistency check
- Validate that names, dates, statuses, commands, and issue references match the project state.
- Check that headings, labels, and terminology are consistent throughout the file.
- Ensure any examples or instructions align with the actual implementation or workflow.

## 3. Completeness check
- Make sure no required task, acceptance criterion, or instruction is omitted.
- Confirm there are no placeholder values such as TODO, TBD, or "coming soon" left in final content.
- Verify all linked or referenced files, sections, or issues are accounted for.

## 4. Formatting and readability check
- Check heading levels, spacing, bullets, and tables are clean and readable.
- Ensure code blocks and markdown render correctly without broken syntax.
- Keep language concise and consistent; remove duplicate or contradictory statements.

## 5. Validation and verification check
- Run the relevant validation, lint, test, or build command when applicable.
- Confirm output matches expected behavior rather than assuming correctness.
- If a file contains instructions, verify the steps can actually be executed in the project environment.

## 6. Final review check
- Read the file once as a user would see it before finalizing.
- Confirm the document answers the intended question or fulfills the required purpose.
- Check for typos, missed references, and any content that could confuse a reader or reviewer.

## Quick reminder
A file is only ready when it is structurally complete, factually correct, readable, and verified against the actual project state.
